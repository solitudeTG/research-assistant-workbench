# F018.8 Evidence Gate Reset Spec

## Background

F018.7 improved the placement of evidence filtering, but manual validation showed the deeper design flaw: semantic relevance was still implemented as deterministic keyword rules. This created a patch loop where every new bad example invited another rule.

The reset principle is:

```text
rules may reject garbage, but only an evidence gate may promote candidates into evidence
```

## Goals

- Stop adding topic-keyword rules for semantic evidence relevance.
- Keep deterministic filtering only for hygiene: empty pages, navigation text, code/markup dumps, administrative metadata, reference fragments, and overly short fragments.
- Add an `EvidenceGateAgent` boundary that decides whether a hygienic candidate is relevant to the user's research question and can be used by audit/composition.
- Ensure `Document Composer Agent` receives only evidence accepted by the evidence gate.
- If no evidence is accepted, produce an evidence-insufficient report instead of filling the report with unrelated content.

## Non-Goals

- No new visible fourth subagent in F018 UI. The gate is part of the evidence-audit boundary for this slice.
- No parallel runtime.
- No durable citation persistence.
- No broad retrieval rewrite.
- No F019 intent classifier work.

## Contract

`EvidenceCurator`:

- Performs deterministic hygiene filtering only.
- Does not reject candidates because they are off-topic.
- Does not maintain domain keyword lists.

`EvidenceGateAgent`:

- Receives the question and hygienic candidates.
- Returns accepted/rejected evidence decisions.
- For each rejection, records a concise reason such as `not relevant to the research question`.
- Is replaceable: tests may use a deterministic fake gate; production can use a model-backed implementation.

Plan-Execute:

- `Deep Research Agent` gathers raw candidates.
- `EvidenceCurator` removes only deterministic garbage.
- `EvidenceGateAgent` promotes relevant candidates into accepted evidence.
- `Evidence Audit Agent` audits the accepted packet.
- `Document Composer Agent` formats the accepted packet.

## Acceptance Criteria

- A regression test proves biomedical/biology/quantum/CAR-T candidates are not accepted for a satellite-interference research question.
- A regression test proves satellite/LEO/interference/beamforming evidence remains accepted.
- A test proves `EvidenceCurator` no longer rejects off-topic-looking but hygienic text by keyword; semantic rejection belongs to `EvidenceGateAgent`.
- A Plan-Execute test proves audit/composer receive the gate-accepted packet, not all hygienic candidates.
- The report must not place curation/audit internals such as `Rejected 9 raw evidence candidate` in the main evidence section.
