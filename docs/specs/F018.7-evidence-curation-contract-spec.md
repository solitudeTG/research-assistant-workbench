# F018.7 Evidence Curation Contract Spec

## Background

Manual validation showed that F018.6 still allowed irrelevant raw web snippets to reach the final report. The failure was not a rendering bug and not only a `Document Composer Agent` quality issue. The deeper boundary problem is that the workflow treats every retrieved paper or web string as report-ready evidence.

F018.7 introduces a small deterministic curation contract between `Deep Research Agent` and the downstream audit/composition steps. The first principle is:

```text
retrieved candidate != accepted evidence
```

## Goals

- Separate raw retrieval candidates from evidence that is eligible for audit and report composition.
- Reject obvious off-topic, empty, administrative, reference-list, navigation, and code/markup fragments before audit.
- Preserve the existing three visible subagents: `Deep Research Agent`, `Evidence Audit Agent`, and `Document Composer Agent`.
- Keep F018 serial and Supervisor-led; the curation layer is an orchestration guardrail, not a new planner or a fourth visible subagent.
- Make the curation decision observable enough for tests and later UI projection.

## Non-Goals

- No LLM reranker.
- No embedding search or semantic ranking service.
- No durable citation persistence.
- No F019 intent-classifier work.
- No parallel worker runtime.
- No Composer-side retrieval.

## Contract

`EvidenceCurator` receives `(question, ResearchPacket)` and returns a `CuratedEvidenceSet`.

Accepted items:

- Keep the original source type: `paper` or `web`.
- Must contain topic-relevant terms derived from the user question and domain synonyms.
- Must not be an empty-page/navigation message such as `No information is available for this page`.
- Must not be a reference-list fragment, administrative metadata, affiliation/grant note, or obvious code/markup dump.

Rejected items:

- Record source type, original text, reject reason, and matched topic terms.
- Rejection reasons are deterministic strings:
  - `OFF_TOPIC`
  - `EMPTY_OR_NAVIGATION_PAGE`
  - `ADMINISTRATIVE_METADATA`
  - `REFERENCE_FRAGMENT`
  - `CODE_OR_MARKUP`
  - `TOO_FRAGMENTED`

Curated packet:

- Downstream `EvidenceAuditAgent` and `DocumentComposerAgent` consume only accepted evidence.
- If all raw evidence is rejected, the curated packet must add an evidence gap explaining that no topic-matched evidence survived curation.
- Raw evidence can remain trace/debug data later, but must not be used as final report evidence.

## Acceptance Criteria

- A test proves irrelevant web content about unrelated geopolitics is rejected for a satellite-interference question.
- A test proves `No information is available for this page` is rejected.
- A test proves relevant LEO/satellite/interference/beamforming evidence is retained.
- A Plan-Execute test proves audit and composer receive the curated packet, not the raw packet.
- The final report must not include rejected web snippets.
- Existing F018 ReAct/Plan-Execute behavior and visible subagent count remain stable.
