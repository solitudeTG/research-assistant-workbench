# F017 Session Delete and Review Sidebar Spec

## 背景

当前研究工作台已经有项目级会话、回答证据、候选确认、知识板和研究过程事件。但真实 UI 暴露出三个问题：

- 会话列表只支持改名，不支持删除这种常规管理动作。
- 右侧栏把知识、证据、候选并列展示，用户难以判断它们和中间研究过程中的命中/证据有什么区别。
- 真实数据链路中证据较稳定，知识和候选可能为空，当前空状态容易让用户误以为系统坏了。

第一性原理判断：这里不应该用“填假数据”解决空面板，而应该重新声明信息生命周期。

## 信息边界

### 研究过程

中间对话里的研究过程展示本轮回答的生成轨迹，包括工具调用、资料检索、记忆召回、证据评估和回答生成。它回答的问题是：

```text
系统为了生成这次回答，做过哪些步骤？
```

这里的命中可以是过程命中，不等于最终回答引用。

### 最终证据

右侧审阅区的证据展示当前回答最终采用的引用来源。它回答的问题是：

```text
这次回答最终由哪些来源支撑？
```

证据来源可以来自本地论文、项目知识、联网补充或会话记忆，但必须围绕当前回答上下文展示。

### 候选

候选是 AI 从回答或会话中提炼出的知识草稿。它回答的问题是：

```text
这次回答里有哪些值得用户确认后沉淀的结论？
```

候选为空是合法状态，表示本轮尚未生成候选或后端没有产生候选事件；UI 必须明确说明，不应伪装成加载失败。

### 知识

知识是用户确认后的项目级长期记忆。它回答的问题是：

```text
这个研究项目已经确认沉淀了什么？
```

完整知识管理属于一级“知识”工作区。会话右侧只提供当前回答相关的摘要、入口或紧凑预览。

## 会话删除语义

用户确认本 Feature 采用真删除。

删除会话必须满足：

- 用户发起删除后需要二次确认。
- 取消确认不得修改前端状态或后端数据。
- 确认后调用项目边界内的删除 API。
- 删除是项目内受限操作，跨项目 sessionId 必须返回 `404`。
- 删除后该会话的研究痕迹不可继续通过当前 UI 召回。

本项目当前 schema 对部分会话外键使用 `on delete set null`。因此实现不得只执行 `delete from research_session`。后端必须显式清理该 session 下的：

- `chat_message`，通过 legacy `chat_session.session_key = research_session.id` 找到真实数值 session。
- `memory_entry`，同样通过 legacy chat session 清理当前会话记忆沉淀。
- `retrieval_trace`，通过 legacy chat session 清理当前会话旧诊断记录。
- `assistant_answer`，按 `project_id` 和 `session_id` 删除。
- `evidence_source`，由 `assistant_answer` 外键级联删除。
- `answer_feedback`，由 `assistant_answer` 外键级联删除。
- `knowledge_candidate`，按 `project_id` 和 `session_id` 删除。
- `stream_event_record`，按 `project_id` 和 `session_id` 删除。
- `research_session` 本身。

已确认的 `knowledge_entry` 不按会话直接删除，因为它是用户确认后的项目级长期知识。若它来自被删候选，既有外键会把候选引用置空；这是合理的知识保留边界。

## API

### DELETE /api/projects/{projectId}/sessions/{sessionId}

成功：

```text
204 No Content
```

失败：

- 项目不存在：`404`
- 会话不存在或不属于项目：`404`

## UI 行为

### 会话列表

每行会话展示：

- 会话标题。
- 状态和最近更新时间。
- 操作入口。

操作入口至少包含：

- 重命名。
- 删除。

删除动作必须出现二次确认文案：

```text
删除会话“{title}”？这会删除该会话的消息、回答、证据、候选和研究过程记录，无法撤销。
```

删除成功后：

- 从本地 `sessions` 移除该会话。
- 如果删除的是当前会话，切换到剩余第一条会话。
- 如果没有剩余会话，清空当前会话上下文并允许用户新建会话。
- 清空当前回答、消息、证据、当前候选上下文和诊断选择。

### 当前回答审阅区

右侧栏语义改为当前回答审阅区：

- 顶部上下文文案必须围绕当前回答。
- `证据` tab 展示最终引用来源。
- `候选` tab 展示待确认候选。
- `知识` tab 展示项目知识摘要和完整知识工作区入口。

空状态：

- 证据为空：`当前回答还没有最终引用。回答完成并完成证据评估后会显示。`
- 候选为空：`本轮尚未生成待确认候选。开启“提炼候选”后，回答完成时会出现在这里。`
- 知识为空：`项目还没有确认知识。候选确认或手动新建后会进入知识工作区。`

### 研究过程文案

中间研究过程中的“证据与记忆”改为“过程命中”，并说明它是检索/记忆召回过程，不等于最终引用列表。

## 验证

后端：

- `ProjectControllerTest` 覆盖删除成功、跨项目/不存在会话 `404`、删除后列表不包含该会话。
- Repository 或 controller 测试覆盖关联数据清理。

前端：

- `workbench-model.test.mjs` 覆盖本地删除状态转换。
- 如需要新增测试文件，保持在 `src/main/resources/static/tests`。

人工/浏览器：

- 打开工作台，确认会话行操作不挤压文本。
- 点击删除后出现二次确认。
- 取消不会删除；确认后会话消失并切换上下文。
- 右侧栏和研究过程文案不再混淆“过程命中”和“最终证据”。
