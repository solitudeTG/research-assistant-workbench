# Markdown Harness 作为事实源

## 决策

使用 `docs/` 下的 Markdown Harness 文档作为活跃工作、决策和证据的事实源。任何搜索索引、摘要或未来仪表盘都只能作为编译产物。

## 背景

下一轮迭代很可能由多个 Agent 并行完成大规模重构。主要风险不是代码写得太少，而是随着代码量增长，意图、写入边界和验证证据丢失。

## 备选方案

- 数据库化 Harness 注册表：查询能力更强，但在产品重构前引入过多基础设施。
- 只依赖聊天记忆：当下很快，但跨会话脆弱，也难以评审。
- 不做 Harness：前期最快，但很容易产出不可验证的生成代码，并反复重新发现架构决策。

## 影响

- 正向影响：文档可在 git 中评审，也能被简单脚本校验。
- 正向影响：未来 Agent 不依赖聊天记录也能恢复活跃工作。
- 负向影响：工作状态变化时需要维护少量文档。
- 后续动作：只有当轻量校验不够用时，再增加更强的检查。
